## 6. Auditoria de Privacidade e Isolamento

- **Progresso Pessoal Isolado**: `reading_progress` permanece 100% individual. O progresso em metas coletivas (`collective_goal_progress`) é puramente manual e voluntário (`ADR-004`).
- **Anotações Privadas Isoladas**: Notas (`notes`), destaques (`highlights`) e desenhos (`page_drawings`) nunca são listados ou expostos a terceiros. O compartilhamento de uma nota como citação (`shared_quotes`) copia voluntariamente o texto mediante ação explícita do autor e exige que `notes.user_id == current_user.id`.
- **Clubes Privados Invisíveis**: Usuários não-membros (incluindo administradores da instância que não sejam membros do clube privado) recebem `HTTP 404 Not Found` ao tentar inspecionar leituras coletivas privadas.

## 7. Auditoria dos Filtros Taxonômicos e Consistência de Dados Existentes

1. **Paridade entre Contadores e Listagem**:
   - `taxonomy_service.get_taxonomy_tree()` e `library.list_books()` aplicam os mesmos critérios de visibilidade (`b.is_missing = 0` e `s.is_active = 1`) e contagem distinta (`COUNT(DISTINCT b.id)`).
2. **Prevenção de Sobrescrita de Facetas (`genre`, `origin`, `period`)**:
   - `taxonomy_service.sync_book_taxonomy()` cria registros dedicados em `subjects` para facetas ortogonais (`"{categoria} — Gênero — {genre}"`, etc.), impedindo que a classificação de um livro altere o gênero ou origem de outros livros que compartilham a mesma subcategoria.
3. **Preservação de Classificações Manuais**:
   - `taxonomy_service.infer_and_save_for_book()` verifica `SELECT 1 FROM book_subjects WHERE book_id = ? AND is_manual = 1` e jamais sobrescreve classificações manuais do usuário.
4. **Diagnóstico em Banco Existente (`scripts/diagnose_taxonomy.py`)**:
   - O banco local de desenvolvimento (`data/lectoria.db`, 3 livros) foi inspecionado em modo estritamente *read-only* (`?mode=ro`, `PRAGMA query_only=ON`): `counter_mismatches = 0` e `legacy_shared_facet_subjects = 0`.
   - Para a instância de produção (VPS com o acervo contendo *"Filosofia (33)"*), o script `python3 scripts/diagnose_taxonomy.py` está pronto para execução imediata no pré/pós-deploy sem qualquer risco de escrita.

## 8. Auditoria do Ajuste em `automation_service.py`

Foi realizada auditoria específica sobre a chamada `_dir_snapshots.clear()` em `AutomationSchedulerLoop.start()` e `stop()`:
- **Comportamento no Boot**: Quando `main.py` inicia o servidor, o `lifespan` já executa `library.scan_library()` de forma síncrona na inicialização e, em seguida, chama `automation_service.scheduler_loop.start()`.
- **Por que limpar `_dir_snapshots` em `start()` e `stop()` é seguro e necessário**:
  - A primeira linha de `_run_loop()` chama `check_directory_changes_and_auto_scan()` especificamente para capturar o *snapshot inicial* de `mtime` dos diretórios (`if prev is None: _dir_snapshots[key] = max_mtime`, sem disparar scan).
  - Se `_dir_snapshots` retivesse estado obsoleto de um ciclo anterior no mesmo processo, `start()` dispararia um segundo `scan_library()` concorrente logo após o boot.
- **Custo de I/O em Bibliotecas Grandes**:
  - `check_directory_changes_and_auto_scan()` percorre apenas a árvore de diretórios (`for root, dirs, _ in os.walk(spath)`), executando `os.stat()` **somente nas pastas** (e não nos milhares de arquivos PDF/EPUB individuais). Portanto, registrar o snapshot inicial no `start()` tem custo de I/O desprezível (fração de milissegundo) e garante detecção incremental exata nas rodadas subsequentes de 30 segundos.
- **Validação Automatizada**: Coberto pelo teste `test_automation_service_dir_snapshots_baseline_and_incremental_scan` em `tests/test_v170_library_filters_regression.py`.

## 11. Plano Detalhado de Atualização de Instância Existente (`v1.6.3 → v1.7.0`)

Siga rigorosamente este roteiro ao atualizar a instância de produção (VPS) da versão `v1.6.3` para `v1.7.0`:

### Passo 1 — Pré-Verificação e Backup Manual Consistente (Antes de Atualizar)
```bash
# 1. Acesse o diretório da instalação na VPS
cd /caminho/para/lectoria

# 2. Gere um backup consistente (SQLite Online Backup API + capas personalizadas)
./.venv/bin/python scripts/backup.py --backup
# (Ou via Docker: docker compose exec lectoria python scripts/backup.py --backup)

# 3. Verifique a integridade do banco atual (deve reportar Schema v10 e integrity_check = ok)
./.venv/bin/python scripts/backup.py --verify
```

### Passo 2 — Atualização do Código-Fonte
```bash
# Se operando via systemd / instalação nativa:
sudo systemctl stop lectoria.service
git fetch origin
git checkout main
git pull --ff-only origin main
./.venv/bin/pip install -r requirements.txt
```
*(Ou, se operando via Docker Compose)*:
```bash
git fetch origin
git checkout main
git pull --ff-only origin main
docker compose down
docker compose up -d --build
```

### Passo 3 — Inicialização e Migração Automática `v10 → v11`
Ao iniciar o serviço (`sudo systemctl start lectoria.service` ou `docker compose up -d`), o `database.init_db()` executará automaticamente:
1. Criação de backup pré-migração automático `lectoria_pre_v11_migration.db` em `backups/` (com sufixo único se já existir).
2. Criação atômica das 5 tabelas da Leitura Compartilhada, 10 índices e 6 triggers de integridade.
3. Atualização de `schema_migrations` para a versão `11`.

### Passo 4 — Verificação Pós-Atualização na VPS
```bash
# 1. Verificar saúde HTTP e versão (deve retornar status="ok" e version="1.7.0")
curl -fsS http://127.0.0.1:8765/api/health
curl -fsS http://127.0.0.1:8765/api/auth/status

# 2. Verificar integridade do SQLite pós-migração v11
./.venv/bin/python scripts/backup.py --verify

# 3. Executar diagnóstico read-only dos filtros e contadores taxonômicos (ex.: Filosofia (33))
./.venv/bin/python scripts/diagnose_taxonomy.py --db data/lectoria.db
```

## 12. Plano Detalhado de Rollback (`v1.7.0 → v1.6.3`)

Caso ocorra qualquer anomalia operacional durante ou após a atualização na VPS:

1. **Parar imediatamente o serviço v1.7.0**:
   ```bash
   sudo systemctl stop lectoria.service
   # (Ou via Docker: docker compose down)
   ```
2. **Restaurar o backup pré-migração v10**:
   ```bash
   # Liste os backups disponíveis (inclui o backup manual do Passo 1 e o lectoria_pre_v11_migration.db)
   ./.venv/bin/python scripts/backup.py --list

   # Restaure o backup v10 desejado
   ./.venv/bin/python scripts/backup.py --restore <nome_do_arquivo_backup_v10.db>
   ```
3. **Reverter o código para a tag estável `v1.6.3`**:
   ```bash
   git checkout v1.6.3
   ```
4. **Verificar integridade e reiniciar o serviço**:
   ```bash
   ./.venv/bin/python scripts/backup.py --verify
   sudo systemctl start lectoria.service
   # (Ou via Docker: docker compose up -d --build)
   ```
